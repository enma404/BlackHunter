# ============================================================
# Notes for testers
# ============================================================
# 1. Stay in scope. Internal network ranges are almost always
#    OUT of scope for a standard external pentest. Only use
#    these if the client's RoE explicitly includes internal
#    hosts, and only from a position (VPN/jump host) they
#    have authorized.
#
# 2. These payloads are most useful for:
#    - Confirming blind SSRF via OOB (interactsh, Collaborator)
#    - Mapping internal DNS resolution
#    - Discovering internal admin panels exposed to the app
#
# 3. Don't brute-force the whole RFC1918 space. Target the
#    specific hosts the client tells you about, or use a small
#    curated list like this one.
#
# 4. The "service-oriented" hostnames are guesses. Use the
#    client's asset inventory if available.
#
# 5. Watch response timing and error messages. A fast 200, a
#    fast 404, and a slow timeout each tell you something
#    different about the internal host.
#
# 6. If you reach an internal service, STOP and report it.
#    Do not pivot, do not extract data, do not authenticate
#    unless the RoE explicitly allows it.
# ============================================================
