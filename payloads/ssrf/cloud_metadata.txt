# ============================================================
# Notes for testers
# ============================================================
# 1. Required headers per provider (often the "auth" for IMDS):
#    - AWS IMDSv2  : PUT /latest/api/token  + X-aws-ec2-metadata-token-ttl-seconds: 21600
#    - GCP         : Metadata-Flavor: Google
#    - Azure       : Metadata: true
#    - OCI v2      : Authorization: Bearer Oracle
#    - IBM         : Metadata-Flavor: ibm
#    If your SSRF primitive cannot set headers, target IMDSv1 (AWS),
#    DigitalOcean, or Alibaba — those work with plain GET.
#
# 2. The single most valuable target is:
#       AWS : /latest/meta-data/iam/security-credentials/<role>
#       GCP : /computeMetadata/v1/instance/service-accounts/default/token
#       Azure: /metadata/identity/oauth2/token
#    These return temporary cloud credentials.
#
# 3. Never store retrieved credentials in plaintext logs. If a
#    credential is returned, report it to the client immediately
#    and rotate it.
#
# 4. Use out-of-band (Burp Collaborator, interactsh) to confirm
#    blind SSRF before attempting to read responses.
#
# 5. For IMDSv2-only environments, look for a separate SSRF with
#    method control (PUT) and header injection.
# ============================================================
