# ============================================================
# BlackHunter — Upload Payloads: PHP Shells

# Purpose : Verify whether an uploaded PHP file executes on the
#           target. Used AFTER a file-upload vulnerability has
#           been confirmed (see vulns/upload.py).
# Use     : Authorized testing ONLY. See docs/ethical_guidelines.md
# Format  : Each entry is a block delimited by [name] ... [/name].
#           The "filename" directive sets the recommended name.
#           The body between ---BEGIN--- and ---END--- is the
#           exact file content to write to disk.

#           engagement, prefer the harmless "proof" payloads
#           (phpinfo, echo) to confirm execution. Only upload a
#           command shell if the RoE explicitly allows it, and
#           remove it before the engagement ends.
# ============================================================

# ============================================================
# Notes for testers
# ============================================================
# 1. Confirm execution BEFORE uploading a real shell.
#    Upload proof.php, request it, and look for the literal
#    string "BLACKHUNTER_UPLOAD_OK". If you don't see it, the
#    file was uploaded but not executed — move on to bypass
#    techniques (extensions.txt, mime_types.txt, .htaccess).
#
# 2. Short tags (`<?=`) require short_open_tag=On (default
#    since PHP 5.4 for `<?=`). If they fail, use `<?php`.
#
# 3. disabled_functions and open_basedir are the two most
#    common blockers. Always run recon.php first to see what
#    is available before assuming a shell is broken.
#
# 4. WAF bypass: the obfuscated variants (concat, chr, base64,
#    reflection, variable functions) are ordered from mildest
#    to most aggressive. Try them in order.
#
# 5. .htaccess works only on Apache with AllowOverride set.
#    .user.ini works on PHP-FPM/CGI (not mod_php).
#
# 6. Do NOT leave a shell behind. Delete it before the
#    engagement ends, and document the exact path + hash in
#    the report as evidence of the finding.
#
# 7. On a real engagement, prefer a single, minimal proof
#    payload. A dozen shells in an upload directory is noisy
#    and dangerous if the client's monitoring is slow.
# ============================================================
