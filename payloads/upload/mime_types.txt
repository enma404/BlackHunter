# ============================================================
# BlackHunter — Upload Payloads: MIME / Content-Type Bypass
# ============================================================
# Purpose : Enumerate Content-Type headers, magic-byte prefixes,
#           and multipart tricks that may slip past an upload
#           filter that trusts MIME type over actual content.
# Use     : Authorized testing ONLY. See docs/ethical_guidelines.md
# Format  : Each entry is a block delimited by [name] ... [/name].
#           Directives:
#             content_type : value to send in the Content-Type header
#             magic        : magic-byte prefix to prepend to the shell body
#             note         : short description
#             applies_to   : php | jsp | any
#           Lines starting with '#' are comments.
# Warning : Prepend magic bytes to a real shell can break the
#           shell's syntax. Use a polyglot body (see php_shells.txt
#           and jsp_shells.txt) so both the magic bytes and the
#           code remain valid.
# ============================================================

# ============================================================
# Notes for testers
# ============================================================
# 1. Two independent checks are usually in play:
#      a) Content-Type header inspection
#      b) Magic-byte / file-signature sniffing
#    The blocks above are split so you can isolate which one
#    is enforced. Start with section 1 (header-only), then
#    section 2 (magic-only), then section 3 (mismatch).
#
# 2. A polyglot body must satisfy BOTH the magic-byte check
#    AND the server's code parser. Use the polyglot shells in
#    php_shells.txt / jsp_shells.txt (GIF89a + <?php ... ?>).
#
# 3. Some servers re-encode the upload (e.g., recompress
#    images). If so, magic-byte tricks fail because the
#    re-encoded file no longer contains your code. Fall back
#    to extension tricks (extensions.txt) or non-image types
#    (PDF, SVG, XML).
#
# 4. SVG and XML are high-value: they bypass most image-only
#    checks, and they carry XXE / stored XSS payloads. Always
#    try them if image polyglots fail.
#
# 5. Office formats (DOCX/XLSX/PPTX) are ZIP files. If the
#    server extracts them, you can smuggle a shell inside the
#    archive (zip-slip + execution).
#
# 6. Duplicate Content-Type headers (section 6) are parser-
#    dependent. Test both orders; document which one the
#    target honored.
#
# 7. Content-Transfer-Encoding (section 7) only matters if the
#    upload pipeline decodes it. If the app stores the raw
#    body, the encoded payload is inert.
#
# 8. Do NOT upload a working shell unless the RoE allows it.
#    The proof string "BLACKHUNTER_UPLOAD_OK" is enough to
#    demonstrate the finding.
# ============================================================
