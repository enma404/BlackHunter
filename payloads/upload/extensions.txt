# ============================================================
# BlackHunter — Upload Payloads: Extension Bypass Matrix
# ============================================================
# Purpose : Enumerate filename mutations that may slip past a
#           naive extension blacklist/whitelist. Each entry is a
#           transformation rule applied to a base filename
#           (e.g., "shell.php" or "shell.jsp").
# Use     : Authorized testing ONLY. See docs/ethical_guidelines.md
# Format  : Each entry is a block delimited by [name] ... [/name].
#           Directives:
#             template : filename pattern with {base} and {ext}
#             note     : short description
#             os       : linux | windows | any
#             server   : apache | nginx | iis | tomcat | any
#           Lines starting with '#' are comments.
# Warning : Some of these are destructive to the target's file
#           system (e.g., trailing dot on Windows, NTFS ADS).
#           Only test against systems explicitly in scope.
# ============================================================

# ============================================================
# Notes for testers
# ============================================================
# 1. The loader substitutes {base} with the shell's basename
#    (e.g., "shell") and {ext} with the original extension.
#    Example: for shell "php_cmd_get" (filename: cmd.php),
#    the entry [ext_double_php_jpg] produces "cmd.php.jpg".
#
# 2. Not every entry applies to every target. Use the "server"
#    and "os" directives to filter the matrix before running.
#    Example: skip all windows/iis entries when the target is
#    nginx on Linux.
#
# 3. Order matters. Try in this order:
#    a) Alternate PHP/JSP extensions (phtml, php3, php5, jspx)
#    b) Case variants (.PHP, .PhP)
#    c) Double extensions (.php.jpg, .jpg.php)
#    d) Semicolon / trailing dot / space (Apache + Windows)
#    e) NTFS ADS (Windows)
#    f) Null byte (legacy PHP)
#    g) .htaccess / .user.ini re-mapping (upload the config
#       first, then the payload with a benign extension)
#    h) Polyglot with magic bytes (pair with mime_types.txt)
#
# 4. Some servers verify the file's magic bytes, not just the
#    extension. If the payload is rejected for "invalid image",
#    prepend GIF89a / PNG / JPEG magic and retry.
#
# 5. Do NOT leave orphaned files or broken .htaccess on the
#    target. Clean up before the engagement ends, and list
#    every uploaded path in the report.
#
# 6. If the target strips/renames uploads to a safe extension,
#    skip extension tricks entirely and look for:
#      - Path traversal in the filename (../../shell.php)
#      - ZIP extraction with traversal (zip-slip)
#      - Content-Type trust (see mime_types.txt)
#      - Server-side processing of uploaded XML/SVG (XXE)
# ============================================================
